# Agent Presets v1 draft

Status: **draft**

Agent presets are project templates for the AI/Agent Builder.

A preset does not introduce new Core behavior. It selects a set of Flow templates, model roles, capability requirements, storage conventions, and default policies that can be expanded into an ordinary Open LLM Learner project.

The generated project remains editable after creation.

## Preset format

Preset files use the suffix:

```text
*.agent-preset.json
```

Official presets live under:

```text
presets/agents/
```

A preset declares:

- human-readable name and description;
- source/basis information;
- required model roles;
- required MOD capabilities;
- project workspace layout;
- lifecycle flows the preset expects;
- default policies;
- user-overridable parameters.

Presets must not rely on private official-only APIs.

## WikiSkill-derived presets

The initial research-derived preset family is based on:

> WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution  
> Liyan Tang, Cyrus Rashtchian, Chun-Sung Ferng, Andrew Tomkins, Da-Cheng Juan, Tu Vu (2026)  
> https://arxiv.org/abs/2608.27454

WikiSkill separates agent state into three layers:

1. **Raw layer** — immutable execution traces.
2. **Wiki layer** — persistent, compounding knowledge extracted from experience.
3. **Skills layer** — active procedural instructions used by the execution agent.

Its evolution loop contains four responsibilities:

1. **Inference Agent** executes tasks with active skills.
2. **Wiki Maintainer** consolidates successful and failed traces into persistent patterns and logs.
3. **Skill Proposer** proposes an atomic skill creation/update using the wiki and recent traces.
4. **Validation Gate** accepts only updates that improve held-out validation performance; rejected skill updates are rolled back while wiki knowledge persists.

### Open LLM Learner adaptation

Open LLM Learner does not require or store hidden model chain-of-thought.

The Raw layer records observable execution information such as:

- task input;
- model-visible messages when available;
- actions;
- tool/MOD calls;
- tool/MOD results;
- final outputs;
- evaluator results;
- errors and execution metadata.

This is enough for the Maintainer and Proposer to analyze behavior without making private reasoning traces part of the project format.

### Preset 1: WikiSkill Standard

Closest product preset to the paper methodology.

Properties:

- separate Raw / Wiki / Skills layers;
- training, validation, and test task splits;
- full active-skill injection into the Inference Agent by default;
- Wiki is unavailable to the Inference Agent during evolution rollouts;
- success/failure trace sampling for Wiki maintenance;
- atomic proposal: one skill create/update per proposal;
- validation score must improve for a skill update to be accepted;
- rejected skill changes roll back;
- Wiki changes persist even when a skill proposal is rejected;
- skill-impact history records accepted and rejected interventions.

This preset is intended for users who want research-style skill evolution and are willing to pay the additional inference/evaluation cost.

### Preset 2: WikiSkill Local Lite

A local-first derivative for smaller machines and models.

It keeps the architectural insight that experience, persistent knowledge, and executable skills are separate, but reduces orchestration cost:

- the same local model may fill Inference, Wiki Maintainer, and Skill Proposer roles;
- smaller sampled rollout batches are expected;
- test split may be deferred until final evaluation;
- validation gating remains mandatory;
- Wiki persistence and skill rollback semantics remain unchanged;
- execution traces remain immutable.

This preset is not intended to reproduce the paper's exact experimental setup. It is a product-oriented low-cost adaptation.

### Preset 3: WikiSkill Teacher -> Local

A transfer-oriented preset motivated by the paper's finding that skills can transfer across models/model families and that skills evolved by a stronger model can outperform self-evolved skills for a smaller execution model.

Roles:

- **Executor**: the local/smaller model that will run the finished agent.
- **Teacher Maintainer/Proposer**: a stronger local or remote model used during skill evolution.
- **Evaluator**: deterministic evaluator or model-based evaluator chosen by the project.

The evolved Skills layer belongs to the project, not to the teacher model. After evolution, the teacher can be removed and the local executor continues to use the accepted skills.

This is especially relevant to Open LLM Learner's goal of making small local models useful for narrow tasks.

## Workspace layout

The default WikiSkill workspace generated by these presets is:

```text
agent/
├─ raw/
│  └─ ...
├─ wiki/
│  ├─ index.md
│  ├─ patterns/
│  │  └─ ...
│  ├─ evolution-log.md
│  └─ skill-impact.jsonl
└─ skills/
   └─ <skill-id>/
      ├─ SKILL.md
      └─ PURPOSE.md
```

`raw/` is append-only from the preset's point of view.

`wiki/` persists across evolution iterations.

`skills/` is the gated executable/procedural layer and may roll back to the last accepted state.

## Lifecycle

A generated project should expose lifecycle entrypoints similar to:

```text
run
evolve
validate
test
```

The exact Flow files are implementation details of the preset.

Conceptually:

```text
              +--------------------+
              | accepted Skills    |
              +----------+---------+
                         |
                         v
task -> Inference Agent -> observable trace -> raw/
                                      |
                                      v
                               Wiki Maintainer
                                      |
                                      v
                                   wiki/
                                      |
                                      v
                               Skill Proposer
                                      |
                                      v
                              candidate Skill
                                      |
                                      v
                                Validation
                                  /      \
                           improve      no improve
                              |             |
                           accept        rollback
                              |             |
                              +-------> skill-impact
                                      |
                                      v
                                wiki persists
```

## Evaluation requirement

WikiSkill-style evolution is only meaningful when the project has an evaluator.

A preset therefore requires one of:

- deterministic ground-truth scoring;
- tests/assertions;
- a domain-specific evaluator MOD;
- an explicitly configured model-based evaluator.

The preset must not silently treat the same model's subjective preference as ground truth.

## Skill portability

Skills are project artifacts separate from model weights.

This means:

- skills may be reused with another compatible model;
- a project may evolve skills with one model and execute them with another;
- weight fine-tuning and skill evolution can be used independently or together.

This separation is deliberate and aligns with Open LLM Learner's principle that weights are only one part of an AI system.
